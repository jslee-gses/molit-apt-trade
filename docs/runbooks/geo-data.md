# 지리 데이터 갱신 절차

좌표와 경계는 공개 파일로만 만든다(외부 지오코딩 API는 결과 저장 금지라 쓰지 않는다).
모든 단계는 사람이 직접 한다. 내려받은 원본(.shp 등)과 연결 문자열은 저장소에 올리지 않는다.

## 처음 한 번 (운영 최초 설정)
순서를 지킨다.
1. **코드 배포** — 마이그레이션이 적용되고 `/login`이 열리는지 확인한다.
2. **위치정보요약DB 적재(A)** — 좌표의 원천이다.
3. **첫 경계 버전 커밋·배포(B)** — 경계 폴더가 배포에 포함되어야 서버가 본다.
4. 10분 안에 파이프라인이 단지에 좌표를 연결하고 지역을 판정한다. `/status`의 "좌표 확보 단지"와
   "활성 경계"로 확인한다.

배포 직후 첫 파이프라인 실행은 기존 거래 전체에서 단지를 만드는 일회성 작업이 있다(D 참고).

## A. 위치정보요약DB (월 1회)
1. 주소정보누리집(business.juso.go.kr) → 주소 DB 제공 → **위치정보요약DB** 전체분을 내려받아 압축을 푼다.
2. **처음 한 번은 형식을 확인한다.** 아무 .txt 파일의 첫 줄을 보고 `geo/address_points.py`의 `COLUMNS` 순서
   (시군구코드|출입구일련번호|법정동코드|시도명|시군구명|읍면동명|도로명코드|도로명|지하여부|건물본번|건물부번|건물명|우편번호|건물용도분류|건물군여부|관할행정동|X좌표|Y좌표)
   와 인코딩(CP949), 좌표계(UTM-K, EPSG:5179)가 맞는지 확인한다. 다르면 `COLUMNS`·`--encoding`·`SRC_CRS`를 고친다.
   ```bash
   .venv/Scripts/python -c "print(open(r'<파일>', encoding='cp949').readline())"
   ```
3. 로컬 DB로 먼저 시험한다(로컬에 거래가 없으면 공동주택만 적재된다):
   ```bash
   .venv/Scripts/python -m geo.address_points --dir <폴더> --month 202609
   ```
   **처음 한 번은 출력 통계를 확인한다.**
   `파일 N개 · …줄 · 공동주택 …줄 · 건너뜀: 열 부족 …, 키 오류 …, 숫자 오류 …, 좌표 범위 밖 …`
   - **공동주택 0줄**이면 인코딩(`--encoding`)이나 열 순서가 틀린 것이다. 이때 도구는 적재하지 않고 종료 코드 1로 끝난다.
   - 건너뜀 수가 전체 줄에 비해 크면(열 부족·키 오류가 많으면) 형식이 다른 것이니 `COLUMNS`를 다시 확인한다.
   - "좌표 범위 밖"은 한반도 밖이거나 유한하지 않은 좌표를 버린 수다. 소수여야 한다.
4. 운영 DB에 적재한다. **먼저 3번 출력의 "파일 N개"가 전국 전체 분량과 맞는지 확인한다**
   (일부 폴더만 주면 테이블 전체가 그 일부로 교체된다). readme·안내 .txt 때문에 "열 부족"이 조금 나오는 것은 정상이다. Railway → Postgres 서비스 → Connect → **Public Network** 연결 문자열을 복사해 쓴다(저장소·채팅에 남기지 않는다).
   로컬이 아닌 DB는 `--yes`가 없으면 종료 코드 1로 멈춘다. `--database-url`로 넘기면 비밀번호가 셸 기록에 남으므로,
   그 셸에서만 환경변수로 설정해 쓰고 끝나면 셸을 닫는다(PowerShell):
   ```powershell
   $env:DATABASE_URL = "<공개 연결 문자열>"
   .venv/Scripts/python -m geo.address_points --dir <폴더> --month 202609 --yes
   ```
   - 시작할 때 `대상 DB: host:port/dbname`이 출력된다(비밀번호는 가려진다). **운영 DB가 맞는지 확인**한다.
   - 테이블을 통째로 교체하고, 좌표를 못 찾았던 단지를 다시 찾게 한다.
   - 끝의 "적재 …건 · 거래 도로명주소 키 … 중 … 일치"의 일치 비율을 기록한다. 10분 안에 `/status`의 좌표 확보 단지가 늘어난다.
   - 이 도구는 마이그레이션을 하지 않는다(스키마는 배포된 앱이 관리). 코드를 먼저 배포해야 한다.

## B. 읍면동 경계 (분기·반기 1회)
1. 브이월드(vworld.kr) 또는 국가공간정보포털(nsdi.go.kr)에서 **읍면동 경계(LT_C_ADEMD_INFO)** SHP를 내려받는다.
2. 경계 파일을 만든다:
   ```bash
   .venv/Scripts/python -m geo.boundaries --shp <파일.shp 또는 .zip> --version 2026-10 --source "브이월드 LT_C_ADEMD_INFO 2026-09"
   ```
   - `--version`은 **반드시 `YYYY-MM`** 형식이다(`2026-10`). 다른 이름의 폴더는 서버가 버전으로 인식하지 않는다.
   - 새 버전 이름은 **활성 버전보다 문자열로 더 뒤(나중 달)**여야 한다. 서버는 버전을 한 번만 등록하고
     활성 버전보다 새로운 버전으로만 전환한다. 잘못 만든 경계를 고쳐 다시 만들 때도 같은 이름을 쓰지 말고
     더 나중 이름(예: 2026-11)으로 만든다. 옛 폴더로 되돌리는 전환은 지원하지 않는다
     (롤백 = 옛 자료를 더 나중 이름으로 다시 만들어 배포).
   - `--src-crs EPSG:5186`: 파일에 .prj가 없을 때만 지정한다.
   - `--encoding cp949`: 한글 이름이 깨질 때 지정한다(기본은 자동).
   - 잘못된 도형은 자동으로 고치며(make_valid), 면적이 없어 제외한 경계가 있으면 개수를 경고로 출력한다.
   - "lawd_codes.csv에 없는 …" 목록이 나오면: 경계 파일이 최근 개편을 반영하지 못한 것이다.
     `geo/code_map.csv`에 `옛 읍면동 코드,새 읍면동 코드`를 한 줄씩 넣고 다시 실행한다.
     (lawd_codes.csv 쪽이 틀렸다면 그 파일을 고친다.)
   - 끝에 만든 파일의 크기가 출력된다. **전국 경계를 처음 만들 때는 크기를 확인한다.**
     `geo_data/<버전>/umd_assign.geojson.gz`는 서버가 메모리에 올려 쓰므로 매우 크면(수십 MB 이상) 보고한다.
3. 결과(`static/geo/2026-10/`, `geo_data/2026-10/`)를 커밋·배포한다. 이전 버전 폴더는 다음 커밋에서 지운다.
4. 배포 후 10분 안에 서버가 새 버전을 등록하고 모든 단지를 재판정한 뒤 전환한다. `/status`의 "활성 경계"로 확인한다.
   - 새 버전으로의 전환이 실패해도 좌표 연결·지역 판정은 멈추지 않고 기존 경계로 계속된다.
   - 실패 내용은 `/status` 하단 "마지막 처리 …" 줄에 오류로 표시된다. 같은 버전은 **1시간 뒤** 다시 시도한다.
   - 원인(파일 누락·형식 오류 등)을 고쳐 다시 배포하면 된다. 서버를 재시작하면 대기 시간 없이 바로 다시 시도한다.

## C. 좌표를 못 찾은 단지
`/status` → "좌표를 찾지 못한 단지"에서 경도·위도를 넣고 저장한다(지도 서비스에서 눈으로 찾은 값 입력은 괜찮다.
API로 대량 조회해 저장하는 것은 이용 조건 위반이다).

## D. 단지 최초 생성 (배포 후 첫 실행 한 번)
`complexes.bootstrap`은 배포 후 첫 파이프라인 실행에서 한 번만 돌아, 기존 `trades` 전체에서 단지를 만든다
(완료하면 `app_flags`에 `complexes_bootstrapped` 표식을 남긴다). 거래 전체를 한 번에 정렬하므로
거래가 많은 운영 DB에서는 **첫 실행이 몇 분 걸릴 수 있다.**
- 시간 초과 등으로 실패하면 단지를 만드는 INSERT와 표식 쓰기가 함께 취소된다. 실패는 기록(`bootstrap_error`)만 하고
  좌표 연결·지역 판정 등 나머지 단계는 그대로 이어서 실행한다. 그냥 두면 다음 10분 주기에 다시 시도한다
  (표식이 쓰이기 전까지 반복해도 안전하다).
- 계속 실패하면 한도를 늘린다: `ALTER DATABASE <db> SET statement_timeout = '30min';` (필요하면 `work_mem`도 같은 방식으로 올린다).
  새 설정은 새 연결부터 적용된다. `complexes_bootstrapped` 표식이 쓰인 것을 확인한 뒤 `ALTER DATABASE <db> RESET statement_timeout;`
  (`RESET work_mem`)으로 되돌린다.
  단, 단지 생성 뒤 적재한 주소 좌표(A)로 처음 좌표 연결(LOCATE)이 끝날 때까지는 올린 `statement_timeout`을 유지한다
  (그 첫 LOCATE는 전체 거래를 한 번 훑는다).
- 진행 여부는 `/status`의 "마지막 처리 …" 줄(오류 표시)로 확인한다.
