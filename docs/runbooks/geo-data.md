# 지리 데이터 갱신 절차

좌표와 경계는 공개 파일로만 만든다(외부 지오코딩 API는 결과 저장 금지라 쓰지 않는다).
주소정보누리집 위치정보요약DB는 받을 때 "국외 반출 금지" 조건이 붙어 쓰지 않는다(운영 서버가 해외).
모든 단계는 사람이 직접 한다. 내려받은 원본(.shp 등)과 연결 문자열은 저장소에 올리지 않는다.

## 처음 한 번 (운영 최초 설정)
순서를 지킨다.
1. **코드 배포** — 마이그레이션이 적용되고 `/login`이 열리는지 확인한다.
2. **첫 경계 버전 커밋·배포(B)** — 경계 폴더가 배포에 포함되어야 서버가 본다. 이때부터 모든 단지가 법정동 코드로 판정된다.
3. **연속지적도로 단지 좌표 만들기(A)**
4. 10분 안에 파이프라인이 좌표 있는 단지를 경계로 다시 판정한다. `/status`의 "좌표 확보 단지"와 "지역 판정"으로 확인한다.

배포 직후 첫 파이프라인 실행은 기존 거래 전체에서 단지를 만드는 일회성 작업이 있다(D 참고).

## A. 연속지적도로 단지 좌표 만들기 (필요할 때)
`/status`의 "좌표 없음(대기)"이 쌓이면 실행한다. 좌표가 없어도 읍면동 집계는 법정동 코드로 채워지므로 급하지 않다.
1. 브이월드(vworld.kr) → 공간정보 다운로드 → **연속지적도형정보**(국토교통부, **CC BY**). 시·도마다 구분 **전체데이터**·형식 **SHP**의
   최신 기준일 파일(`AL_D002_<시도>_<기준일>.zip`)을 받아 한 폴더(예: `D:\geo_src\연속지적도형정보\전국_YYYYMM`)에 모은다.
   **시도마다 파일 하나만** 둔다(같은 시도의 여러 기준일이 섞이면 나중 파일 값이 쓰인다). 2026-09 기준 16개 시도
   (광주·전남은 전남광주통합특별시 `12` 하나), 합계 약 6.3GB, 필지 약 3,990만 개(읽는 데 3~5분).
   - 일별 변동분(`CH_D002_*`)과 옛 기준일 파일은 넣지 않는다. 받은 폴더에 섞여 있으면 최신 전체본만 하드 링크로 모은 폴더를 따로 만든다
     (PowerShell: `New-Item -ItemType HardLink -Path <새폴더>\<파일> -Target <원본>`, 용량이 늘지 않는다).
   - 화면 하단 출처 표시(`templates/base.html`, "단지 위치: 국토교통부 연속지적도형정보(CC BY)")를 지우지 않는다.
2. 로컬 DB로 먼저 시험한다(저장 없음):
   ```bash
   .venv/Scripts/python -m geo.parcel_points --dir <폴더> --dry-run
   ```
   출력: `zip N개 · 필지 …개 읽음 · 대상 단지 … · PNU 없음 … · 찾음 …(…%, 개편 코드로 찾음 …) · 못 찾음 … · 범위 밖 …`
   - 큰 시도(경기·경북·전남광주 등)는 zip 하나에 SHP가 여러 조각으로 들어 있다. 도구가 모두 읽는다.
   - 개편 전 코드로 신고된 거래(옛 광주·전남, 인천 서구·중구, 화성 등)는 `geo/code_map.csv`로 바꾼 필지번호로도 찾는다.
     2026-09 전국 시험(공시가격 아파트 필지 46,700개)에서 변환 전 91.5% → 변환 후 99.5%.
   - `PNU 열을 찾지 못했습니다`면 연속지적도형정보 파일이 아니다(GIS건물통합정보·공시가격 파일과 섞이지 않았는지 확인).
3. 운영 DB에 저장한다. 운영 Postgres는 평소 외부 접속이 꺼져 있으므로, **작업하는 동안만 TCP 프록시를 켜고 끝나면 지운다.**
   - **시간대:** TCP 프록시를 만들 때와 지울 때 **Postgres가 각각 재시작**되어 수 초~수십 초 연결이 끊긴다(그 사이 수집 작업 몇 건이
     연결 오류로 기록되고 다음 주기에 자동 재시도). 하루 한도를 다 써 수집이 쉬는 시간대에 한다.
   1. Railway → **Postgres** 서비스 → Settings → Networking → **Public Networking**에서 TCP 프록시를 만든다(포트 **5432**).
      화면 위에 Deploy 버튼이 뜨면 눌러 적용한다. 잠시 뒤 `xxxx.proxy.rlwy.net:<포트> → :5432`가 보인다.
   2. Postgres → Variables의 **`DATABASE_PUBLIC_URL`** 값을 복사한다(호스트가 `….proxy.rlwy.net`).
      `DATABASE_URL`(호스트 `postgres.railway.internal`)은 Railway 안에서만 통해 이 PC에서는
      `failed to resolve host 'postgres.railway.internal'`로 실패한다. 공개 주소 경고(egress 요금)는 이 작업 규모(수 MB)에서는 무시해도 된다.
   3. **프로젝트 폴더에서** 그 셸에만 환경변수로 설정해 실행한다. 연결 문자열은 채팅·저장소·파일에 남기지 않는다(PowerShell):
      ```powershell
      cd D:\molit-trade
      $env:DATABASE_URL = "<DATABASE_PUBLIC_URL 값>"
      .\.venv\Scripts\python.exe -m geo.parcel_points --dir <폴더> --dry-run
      .\.venv\Scripts\python.exe -m geo.parcel_points --dir <폴더> --yes
      ```
      - 시작할 때 `대상 DB: host:port/dbname`이 출력된다(비밀번호는 가려진다). **`….proxy.rlwy.net:<포트>/railway`인지 확인**한다.
      - 연결에 실패하면 연결 오류가 계속 반복 출력된다. Ctrl+C로 멈추고 주소를 확인한다.
      - `--dry-run`의 찾음 비율을 먼저 본다. 2026-10-07 첫 실행: 대상 단지 44,041 · PNU 없음 53 · 찾음 43,341(98.4%) · 못 찾음 647.
      - 좌표가 없는 단지(대기·못 찾음)만 다룬다. 수동 좌표와 이미 찾은 단지는 건드리지 않는다. 저장은 몇 초면 끝난다.
   4. **끝나면 바로** Networking에서 TCP 프록시를 휴지통 아이콘으로 지우고(Deploy가 뜨면 적용), PowerShell 창을 닫는다.
   - 다음 지리 처리(최대 10분 뒤)가 좌표가 생긴 단지를 경계로 다시 판정하고 집계를 다시 계산한다. 4만여 단지면 25분쯤 걸리고
     그동안에도 수집은 계속된다. 끝나면 `/status`의 지역 판정에서 "경계"가 늘고, 지도 읍면동 단계와 단지 상세에 점이 나온다.
   - 이 도구는 마이그레이션을 하지 않는다(스키마는 배포된 앱이 관리). 코드를 먼저 배포해야 한다(없으면 `pnu` 함수가 없다는 오류).

## B. 행정구역 경계 (연 1회 + 행정구역 개편 때)
1. 브이월드 → 공간정보 다운로드에서 국토지리정보원 연속수치지형도 경계 두 가지(**CC BY**)를 내려받는다(속성 `BJCD` 10자리·`NAME`, EPSG:5179).
   - **행정경계(읍면동)** `N3A_G0110000.zip`: https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=MK&dsId=30254
   - **행정경계(시군구)** `N3A_G0100000.zip`: https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=MK&dsId=30252
   - 국토지리정보원 `행정경계(시도)`(dsId=30253)·국토교통부 `행정구역_읍면동(법정동)`·센서스경계는 **CC BY-NC-ND**(변경금지)라
     쓰지 않는다. 전국(시도 단계) 화면은 시군구 원본 경계를 시도별로 칠한다.
   - 화면 하단의 경계 출처 표시(`templates/base.html`)를 지우지 않는다(CC BY 조건).
2. **개편 반영 확인**: 이 자료는 연 1회 갱신이라 최근 개편이 빠질 수 있다. 경계 도구가 "lawd_codes.csv에 없는 …" 목록을
   출력하면 `geo/code_map.csv`(`old_emd_cd,new_emd_cd,old_name,new_name`)에 옛 코드 → 새 코드를 넣는다.
   `new_name`을 채우면 개편으로 바뀐 동 이름도 반영된다. 근거는 행정표준코드관리시스템(code.go.kr)의 법정동 코드 변경 내역이다.
   - 2026-10 버전의 대응표(741줄: 전남광주통합특별시, 인천 제물포구·영종구·서구·검단구, 화성시 4개 구)는
     NGII 2025 경계와 국토교통부 2026-09 경계를 겹쳐 면적이 가장 많이 겹치는 새 동으로 만들었다(1:1, 이름 일치 99.9%).
     코드 대응 사실만 쓰고 국토교통부 도형은 저장소에 넣지 않았다.
   - 대응표만 고쳐 배포해도 서버가 바뀐 것을 알아채 법정동 코드로 판정한 단지를 다시 판정한다(경계 버전을 새로 내지 않아도 된다).
3. 경계 파일을 만든다:
   ```bash
   .venv/Scripts/python -m geo.boundaries --shp <N3A_G0110000.zip> --sgg-shp <N3A_G0100000.zip> --version 2026-10 --source "국토지리정보원 연속수치지형도 행정경계(읍면동 N3A_G0110000·시군구 N3A_G0100000), CC BY"
   ```
   - `--version`은 **반드시 `YYYY-MM`** 형식이다(`2026-10`). 다른 이름의 폴더는 서버가 버전으로 인식하지 않는다.
   - 새 버전 이름은 **활성 버전보다 문자열로 더 뒤(나중 달)**여야 한다. 서버는 버전을 한 번만 등록하고
     활성 버전보다 새로운 버전으로만 전환한다. 잘못 만든 경계를 고쳐 다시 만들 때도 같은 이름을 쓰지 말고
     더 나중 이름(예: 2026-11)으로 만든다. 옛 폴더로 되돌리는 전환은 지원하지 않는다
     (롤백 = 옛 자료를 더 나중 이름으로 다시 만들어 배포).
   - `--src-crs EPSG:5186`: 파일에 .prj가 없을 때만 지정한다.
   - `--encoding cp949`: 한글 이름이 깨질 때 지정한다(기본은 자동).
   - 잘못된 도형은 자동으로 고치며(make_valid), 면적이 없어 제외한 경계가 있으면 개수를 경고로 출력한다.
   - "lawd_codes.csv에 없는 …" 목록이 나오면: 경계 파일이 최근 개편을 반영하지 못한 것이다.
     2번처럼 `geo/code_map.csv`에 넣고 다시 실행한다. (lawd_codes.csv 쪽이 틀렸다면 그 파일을 고친다.)
   - 끝에 만든 파일의 크기가 출력된다. **전국 경계를 처음 만들 때는 크기를 확인한다.**
     `geo_data/<버전>/umd_assign.geojson.gz`는 서버가 메모리에 올려 쓰므로 매우 크면(수십 MB 이상) 보고한다.
   - 화면용 파일은 원본을 1m만 단순화하고 작은 섬도 남긴다. 원본이 도로·하천을 따라 붙인 폭 4m 미만의 띠(선택 테두리가
     꼬리처럼 튀어나옴)만 깎는다. 판정용은 5m 단순화, 띠도 그대로다.
     파일: 전국 `nation.json`(2026-10: 30MB, gzip 전송 7MB) · 시도별 `sgg_<시도>.json`(전남광주 12MB가 가장 큼) ·
     시군구별 `umd_<시군구>.json`(대부분 수백 KB). 정적 파일은 1년 캐시라, 화면은 경계 주소에 배포 버전(`?v=`)을 붙여 받는다.
   - "시군구 원본 대신 읍면동 합을 쓴 곳 N개"가 출력된다. 2026-10은 35개(전남광주 27·인천 4·화성 4)로, 국토지리정보원
     경계(2025년 기준)에 아직 없는 2026 개편 지역이다. 개편이 반영된 새 원본이 나오면 이 수가 줄어든다.
   - 지역 목록·판정용은 그대로 두고 화면용 파일만 다시 만들 때는 같은 버전 이름으로 덮어써도 된다
     (이전 화면 파일 `static/geo/<버전>/*.json`을 먼저 지운다).
4. 결과(`static/geo/2026-10/`, `geo_data/2026-10/`)를 커밋·배포한다. 이전 버전 폴더는 다음 커밋에서 지운다.
5. 배포 후 10분 안에 서버가 새 버전을 등록하고 모든 단지를 재판정한 뒤 전환한다. `/status`의 "활성 경계"로 확인한다.
   - 새 버전으로의 전환이 실패해도 좌표 연결·지역 판정은 멈추지 않고 기존 경계로 계속된다.
   - 실패 내용은 `/status` 하단 "마지막 처리 …" 줄에 오류로 표시된다. 같은 버전은 **1시간 뒤** 다시 시도한다.
   - 원인(파일 누락·형식 오류 등)을 고쳐 다시 배포하면 된다. 서버를 재시작하면 대기 시간 없이 바로 다시 시도한다.

## C. 좌표를 못 찾은 단지
`/status` → "좌표를 찾지 못한 단지"에서 경도·위도를 넣고 저장한다(지도 서비스에서 눈으로 찾은 값 입력은 괜찮다.
API로 대량 조회해 저장하는 것은 이용 조건 위반이다).

## D. 단지 최초 생성 (배포 후 첫 실행 한 번)
`complexes.bootstrap`은 배포 후 첫 파이프라인 실행에서 한 번만 돌아, 기존 `trades` 전체에서 단지를 만든다
(완료하면 `app_flags`에 `complexes_bootstrapped` 표식을 남긴다). 거래 전체를 한 번에 정렬하므로
거래가 많은 운영 DB에서는 **첫 실행이 몇 분 걸릴 수 있다.**
- 시간 초과 등으로 실패하면 단지를 만드는 INSERT와 표식 쓰기가 함께 취소된다. 실패는 기록(`bootstrap_error`)만 하고
  좌표 연결·지역 판정 등 나머지 단계는 그대로 이어서 실행한다. 그냥 두면 다음 10분 주기에 다시 시도한다
  (표식이 쓰이기 전까지 반복해도 안전하다).
- 계속 실패하면 한도를 늘린다: `ALTER DATABASE <db> SET statement_timeout = '30min';` (필요하면 `work_mem`도 같은 방식으로 올린다).
  새 설정은 새 연결부터 적용된다. `complexes_bootstrapped` 표식이 쓰인 것을 확인한 뒤 `ALTER DATABASE <db> RESET statement_timeout;`
  (`RESET work_mem`)으로 되돌린다.
- 진행 여부는 `/status`의 "마지막 처리 …" 줄(오류 표시)로 확인한다.
