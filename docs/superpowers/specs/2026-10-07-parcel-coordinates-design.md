# 단지 좌표를 연속지적도로 만들고 지도에 단지 위치 표시 — 설계

2026-10-07

## 배경
- 단지 좌표는 주소정보누리집 위치정보요약DB로 만들 계획이었다. 그런데 받을 때 "국외 반출 금지", "인터넷 등을 통한 좌표 표시 불가" 조건이 붙었다. 운영 서버(Railway 앱 싱가포르, Postgres 미국)에 적재하면 반출에 해당하므로 쓰지 않는다. 제공기관 문의는 따로 진행 중이다.
- 대안 조사 결과 국토교통부 **연속지적도형정보**(브이월드, CC BY, 시도별 SHP, 전체 월간)가 적합하다.
  - 서울 시험: 실거래 단지 209개 중 100%, 공시가격 아파트 필지 9,597개 중 99.8%의 필지를 찾았다.
  - 필지 안쪽 대표점과 공동주택 건물 중심점의 거리는 중앙값 13m, 95% 68m 이내였다.
  - GIS건물통합정보는 2015년 이후 준공 대단지가 대부분 빠져 있어(매칭 72%) 쓰지 않는다.
- 남은 법률 확인 사항: 공간정보관리법의 국외 반출 제한은 조문상 기본측량성과·공공측량성과가 대상이다. 이 자료는 페이지에 "측량자료로 사용하지 못하는 참조용 도면정보"라고 되어 있어 위험이 낮다고 보지만, 확정된 해석은 아니다.

## 목표
1. 이 PC에서 연속지적도로 단지 좌표를 만들어 운영 DB에 넣는다(로컬 도구, 필요할 때 실행).
2. 좌표가 있으면 경계로 읍면동을 판정하고, 없으면 법정동 코드로 판정해 읍면동 집계가 항상 완전하게 한다.
3. 지도 화면의 읍면동 단계와 단지 상세 화면에 단지 위치를 점으로 표시한다.
4. 위치정보요약DB 관련 코드·테이블·문서를 정리한다.

범위 밖: 배경지도 타일(도로·지명), 정기 자동 갱신, 서버에서 지적도 처리.

## 1. 좌표 만들기 — 로컬 도구 `geo/parcel_points.py`
`geo/address_points.py`를 대신한다.

```
python -m geo.parcel_points --dir D:\geo_src\연속지적도형정보 [--database-url URL] [--dry-run] [--yes]
```

1. **대상 단지:** `complexes` 중 `geocode_status IN ('pending', 'failed')`이다(`manual`·`ok`는 건드리지 않는다).
2. **대표 PNU:** 대상 단지의 거래마다 PNU를 만들고, 거래가 가장 많은 PNU를 고른다(동률이면 작은 값).
   - PNU 19자리 = `sgg_cd`(5) + `umd_cd`(5) + 대지구분(1: `land_cd`가 '2'면 '2'(산), 그 밖은 '1') + 본번(4자리 0채움) + 부번(4자리 0채움, 비면 0000).
   - 숫자가 아니거나 자릿수가 맞지 않으면 그 거래는 PNU를 만들지 않는다.
   - SQL 함수 `pnu(sgg, umd, land, bon, bu)`(마이그레이션, IMMUTABLE)와 같은 규칙의 Python 함수 `geo.keys.pnu`를 둔다. 테스트로 둘의 결과가 같은지 확인한다(`road_key` 방식과 같음).
3. **필지 읽기:** `--dir` 아래 `*.zip`(시도별 `AL_D002_*` SHP)을 하나씩 읽는다.
   - 속성 열 중 19자리 숫자 PNU 열(현재 `A1`)과 도형만 읽고, 필요한 PNU만 남긴다. 열 이름은 첫 행에서 19자리 숫자인 열로 찾고, 없으면 오류로 멈춘다.
   - 같은 PNU가 여러 도형이면 합친다.
   - 대표점은 `representative_point()`(필지 안쪽 보장)로 구하고, 좌표계를 EPSG:5186(파일의 .prj)에서 EPSG:4326으로 바꾼 뒤 소수 6자리로 반올림한다.
   - 한국 범위(경도 124~132, 위도 33~39) 밖이면 버린다.
4. **저장(한 트랜잭션):** `lock_complexes` → 찾은 단지는 다음처럼 바꾼다.
   - `lon/lat`에 대표점, `geocode_status='ok'`, `geocode_source='parcel'`, `geocoded_at=now`
   - `region_*`·`boundary_version`을 NULL로(다음 지리 처리 주기에 경계로 재판정)
   - `ON_REGION_CHANGE` 훅을 바뀌기 전후로 불러 집계 대기열에 넣는다(`set_manual`과 같은 방식).
   - 대상이었지만 못 찾은 단지는 `failed`로 둔다.
   - 저장 시점에 상태가 바뀐 단지(그 사이 `manual` 등)는 건너뛴다(`WHERE geocode_status IN ('pending','failed')`).
5. **안전장치:** `address_points`와 같다.
   - 로컬이 아닌 DB는 `--yes`가 없으면 종료 코드 1로 멈춘다.
   - 시작할 때 `대상 DB: host:port/dbname`을 출력한다(비밀번호는 가린다).
   - `--dry-run`은 저장하지 않고 통계만 낸다.
   - zip이 하나도 없거나, 대상 단지가 0개이거나, 찾은 단지가 0개면 저장하지 않는다.
   - 통계: `zip N개 · 필지 …개 읽음 · 대상 단지 … · PNU 없음 … · 찾음 …(…%) · 못 찾음 … · 범위 밖 …`
6. **메모리:** 시도 하나씩 읽고 필요한 행만 남긴다. 경기도(약 1GB 풀린 크기)도 이 PC에서 처리할 수 있어야 한다. 도형을 뺀 PNU 열로 먼저 거르고, 필요한 행의 도형만 읽는 2단계 읽기를 쓴다(`pyogrio` `where`나 `fids`).

## 2. 지역 판정 — 서버 `geo/assign.py`, `geo/versions.py`, `geo/pipeline.py`
- **판정 규칙** (단지 하나, 활성 경계 버전 V):
  1. 좌표(`ok`/`manual`)가 있으면 경계로 판정한다 → `within` / `nearest`.
  2. 1번에서 못 정했거나(`none`) 좌표가 없으면 코드로 판정한다.
     - `emd = api_sgg_cd + api_umd_cd[:3]`
     - `geo/code_map.csv`에 있으면 새 코드로 바꾼다.
     - 그 코드가 V의 `regions`(level=umd)에 있으면 `code`, 없으면 `none`.
  3. 결과를 `region_umd_cd`, `region_sgg_cd`(umd 앞 5자리), `region_match`, `boundary_version=V`에 저장한다.
  - `sgg_mismatch`는 경계 판정일 때만 계산하고(지금처럼), 코드 판정이면 false다.
- **대상:** `boundary_version IS DISTINCT FROM V`인 모든 단지다(좌표가 없어도). 코드 판정은 DB 안 조인으로 처리하고, 대응표는 판정할 때 임시 테이블에 올린다. 경계 판정은 지금처럼 Python STRtree로 한다.
- **경계 전환** `versions.switch`도 같은 규칙으로 전체를 재판정한다(임시 테이블 → 훅 → 활성화).
- **대응표 변경:** 경계 버전은 그대로 두고 `code_map.csv`만 고쳐 배포하는 경우에도 다시 판정되게 한다. 지리 처리가 시작할 때 `code_map.csv`의 해시를 `app_flags`(`code_map:<sha1>`)와 비교한다. 다르면 `region_match IN ('code','none')`인 단지의 `boundary_version`을 NULL로 해 다시 판정하게 하고, 새 해시를 기록한다(이전 해시 표식은 지운다). 대상이 코드 판정 단지뿐이라 비용이 작다.
- **파이프라인:** 경계 동기화 → 단지 최초 생성 → (대응표 변경 확인) → 판정 → AFTER_RUN(집계). 위치정보요약DB 좌표 연결 단계(`locate_pending`)는 없앤다.
- **단지 등록 UPSERT:** `failed`인 단지에 새 거래가 오면 `pending`으로 되돌리는 동작은 그대로 둔다(다음 도구 실행 대상).

## 3. 지도 화면 — 읍면동 단계 단지 점
- **API** `GET /api/map/complexes?parent=<시군구 5자리>&band&from&to`(기간·면적 규칙은 `/api/map`과 같음)
  - 응답: `{version, parent, band, from, to, complexes: [{apt_seq, apt_nm, lon, lat, n, median_price, median_ppm2}]}`
  - 대상: `region_sgg_cd = parent`이고 좌표가 있는 단지. 기간 안 거래(해제 제외, 면적 구간 적용)로 건수·중위가·㎡당 중위가를 계산한다. 기간 안 거래가 없는 단지도 `n=0`, 값 null로 포함한다(위치는 보이게).
  - 시군구 하나에 단지가 최대 수천 개 수준이라 한 번에 돌려준다. `/api/map`처럼 캐시 헤더를 단다.
- **화면** (`static/js/map.js`, `templates/map.html`):
  - 읍면동 단계에서만 ECharts `scatter` 시리즈를 geo 좌표계 위에 겹친다.
  - 크기: 건수의 제곱근 비례(최소 3px, 최대 14px). 건수 0이면 작은 회색 점.
  - 색: 현재 지표가 `median_price`/`median_ppm2`/`n_trades`면 그 값으로 지도와 같은 색 단계(`--seq-*`, 단계 경계는 단지 값의 분위수). 전년 대비 지표(`yoy_*`)면 단지 값이 없으므로 중립색(`--muted`).
  - 툴팁: 단지명, 건수, 중위가, ㎡당 중위가. 누르면 `/complexes/<apt_seq>`로 간다.
  - 도구 막대에 "단지 표시" 알약(켜짐 기본). URL 상태(`pts=0/1`)로 기억한다.
  - 읍면동 경계 클릭(선택·미니 추이)은 그대로 둔다. 점이 경계 위에 그려지므로 점 클릭이 우선한다.
- 좌표 숫자는 화면 글자로 표시하지 않는다.

## 4. 단지 상세 화면 — 위치 지도
- **API** `GET /api/complexes/<apt_seq>/nearby` → `{version, umd_cd, umd_name, complexes: [{apt_seq, apt_nm, lon, lat, is_self}]}`. 같은 `region_umd_cd`의 좌표 있는 단지이고, 최대 500개다.
- **화면:** 카드 "위치" 하나를 둔다.
  - 그 읍면동 경계(`static/geo/<V>/umd_<시도>.json`에서 해당 코드 하나)를 그리고, 주변 단지는 회색 점, 현재 단지는 강조색(`--accent`) 큰 점으로 표시한다.
  - 툴팁은 단지명이고, 주변 점을 누르면 그 단지로 간다.
  - 좌표가 없으면 카드에 "위치 정보 없음(좌표 미확보)"만 표시하고 지도를 그리지 않는다.
- **배지:** 기존 좌표 배지를 "지역 판정: 경계 / 경계(근접) / 법정동 코드 / 미판정"과 "위치: 필지 / 수동 / 없음"으로 바꾼다. 좌표 숫자는 지운다.

## 5. 수집 현황·출처·문서
- **수집 현황** "단지 좌표와 지역 판정" 영역:
  - 좌표: 필지 N · 수동 M · 대기(pending) P · 못 찾음(failed) F
  - 판정: 경계 N(근접 포함) · 법정동 코드 M · 미판정 K
  - 안내: "좌표가 없는 단지가 쌓이면 로컬 도구(런북 A)를 실행하세요."
  - 위치정보요약DB 건수 표시는 지운다.
  - "좌표를 찾지 못한 단지" 수동 입력 표는 그대로 둔다(지도 서비스에서 눈으로 찾은 값 입력은 허용).
- **출처**(`templates/base.html` 하단): "단지 위치: 국토교통부 연속지적도형정보(CC BY)"로 바꾸고 위치정보요약DB를 뺀다.
- **추출 코드북:** `region_umd_cd` 설명을 "단지 위치(필지 대표점)나 법정동 코드로 판정한 최신 경계 읍면동"으로 바꾼다. 추출에 좌표·판정 방식 열은 넣지 않는다(지금도 없음).
- **런북 `docs/runbooks/geo-data.md` A절**을 "연속지적도로 단지 좌표 만들기"로 고쳐 쓴다(받는 곳, 폴더, dry-run → 운영 실행, 연결 문자열은 셸 환경변수, 실행 시점 판단). README의 지리 설명도 고친다.

## 7. 오류 처리
- 도구:
  - zip이 깨졌거나 PNU 열을 못 찾으면 그 파일 이름과 함께 멈춘다(저장 없음).
  - 좌표 변환 결과가 유한하지 않으면 버리고 "범위 밖"에 센다.
- 판정:
  - 경계 파일이 없거나 깨졌으면 지금처럼 전환 실패로 격리한다.
  - 코드 판정은 DB만 쓰므로 경계 파일과 무관하게 동작한다. 단, 활성 버전이 없으면 판정하지 않는다.
- API: `parent`가 5자리 숫자가 아니면 400, 활성 버전이 없으면 기존 `not_ready` 처리를 따른다.

## 8. 테스트
- `geo.keys.pnu`와 SQL `pnu()`: 일반·산·부번 없음·공백·숫자 아님·자릿수 초과, 그리고 Python과 SQL의 결과가 같은지
- 도구:
  - 작은 SHP(zip) 고정 자료로 PNU 열 찾기, 여러 조각 합치기, 대표점이 필지 안에 있는지, 좌표 변환·범위
  - 대표 PNU 고르기(거래 많은 쪽, 동률)
  - `--dry-run`은 저장하지 않음, 비로컬 DB는 `--yes` 필요
  - `manual` 단지는 건드리지 않음, 저장 시 상태가 바뀐 단지 건너뜀, 못 찾은 단지는 `failed`
  - 훅 호출(집계 대기열)
- 판정:
  - 좌표 → `within`/`nearest`
  - 좌표 없음 → `code`(대응표 변환 포함)
  - 경계 밖 좌표 → `code` 대체
  - 대응표에도 경계에도 없으면 `none`
  - 좌표가 들어온 뒤 재판정
  - 경계 전환 시 전체 재판정 규칙
  - 대응표 해시가 바뀌면 코드 판정 단지 재판정
- API: `/api/map/complexes` 값·필터·빈 결과·잘못된 parent, `/api/complexes/<seq>/nearby`
- 화면: 지도 템플릿의 "단지 표시" 알약, 단지 상세의 위치 카드와 배지(좌표 숫자 없음), 하단 출처 문구, 수집 현황 집계
- 브라우저 확인: 로컬 개발 DB에서 읍면동 단계 점, 단지 상세 위치 지도, 밝은·어두운 테마

## 9. 운영 반영 순서
1. 코드 배포(마이그레이션 005 적용). 이때부터 모든 단지가 법정동 코드로 판정되어 읍면동 집계가 채워진다.
2. 수집 현황에서 코드 판정률을 확인한다. `none`이 많으면 대응표 누락(오래된 코드 변경)을 조사한다.
3. 전국 17개 시도 연속지적도를 받아 도구를 `--dry-run`으로 확인한 뒤, 운영 DB에 실행한다.
4. 10분 안에 경계 판정으로 바뀌고, 지도와 단지 상세에 점이 나온다.
